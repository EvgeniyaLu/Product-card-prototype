# Генератор черновиков карточек товаров

Локальный прототип на Python для генерации карточек товаров с помощью LLM.

Пайплайн:

```text
JSON товара
    ↓
LLM API
    ↓
Проверка результата
    ↓
JSON / Markdown карточка
```

## Соответствие ТЗ

Реализовано:

- Приём данных в формате JSON
- Генерация через LLM API
- SEO-заголовок (до 70 символов)
- SEO-описание (800–1200 символов)
- Структурированный список характеристик
- 3–5 поисковых запросов
- Блок для менеджера («кому подходит» и «какие задачи решает»)
- Выявление отсутствующих или требующих уточнения данных
- Вывод результата в JSON или Markdown
- Обработка ошибок API и входных данных

## Требования

- Python 3.10+
- LLM-сервер с OpenAI-совместимым API
- Поддержка Chat Completions API
- Поддержка JSON Mode

Решение тестировалось с локальной моделью через LiteLLM.

## Настройка окружения

Пример для PowerShell:

```powershell
$env:LLM_BASE_URL="http://localhost:4000/v1"
$env:LLM_MODEL="gemma4-31b-nvfp4"
$env:LLM_TIMEOUT="120"
$env:LLM_API_KEY="your_key"
```

Пример для Bash:

```bash
export LLM_BASE_URL="http://localhost:4000/v1"
export LLM_MODEL="gemma4-31b-nvfp4"
export LLM_TIMEOUT="120"
export LLM_API_KEY="your_key"
```

## Запуск

Сгенерировать результат в JSON:

```bash
python product_card.py examples/dt810.input.json
```

Сгенерировать Markdown:

```bash
python product_card.py examples/dt810.input.json --format markdown
```

Сохранить результат в файл:

```bash
python product_card.py examples/dt810.input.json --output result.json
```

## Основные решения

### Структурированный ответ модели

Модель обязана возвращать JSON фиксированной структуры, который дополнительно проверяется приложением.

### Контроль галлюцинаций

Для повышения достоверности результата выполняются дополнительные проверки:

- контроль структуры ответа;
- контроль обязательных полей;
- контроль появления новых числовых значений;
- контроль отсутствующих характеристик;
- проверка извлечённых параметров относительно исходных данных.

### Обработка ошибок

Реализована обработка:

- некорректного JSON;
- пустых обязательных полей;
- ошибок API;
- таймаутов;
- некорректных ответов модели.

---

## Ограничения

- Решение является локальным прототипом.
- Не реализованы веб-интерфейс, БД и деплой.
- Проверки уменьшают вероятность появления вымышленных характеристик, но не гарантируют их полное отсутствие.
- Перед публикацией карточка требует редакторской проверки.
